# 组合回测

同一个标的上跑多个策略，把各自的信号合成一个下单决策。合成只发生在回测引擎内，不改策略本身。

## 配置

请求 `/api/control/start_backtest` 时传 `strategy_ids` + `combination_config`：

```json
{
  "stock_code": "600036.SH",
  "strategy_ids": ["01", "02", "03"],
  "start": "2024-01-01",
  "end": "2024-12-31",
  "combination_config": {
    "enabled": true,
    "mode": "vote",
    "weights": {"01": 2, "02": 1, "03": 1.5},
    "min_agree_count": 2,
    "tie_policy": "skip"
  }
}
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 传了配置块即默认启用；设 `false` 等于不合成 |
| `mode` | string | `or` | `or` / `and` / `vote`，非法值回落 `or` |
| `weights` | object | `{}` | 策略 ID → 权重，负值按 0 处理，缺省按 1.0 |
| `min_agree_count` | int | `1` | 最小同向策略数，小于 1 按 1 |
| `tie_policy` | string | `skip` | 平票处理：`skip` / `buy` / `sell` |

## 三种模式

**`or`（默认）**：任一策略出信号即通过，不做过滤，等价于关闭合成。

**`and`**：要求所有可运行策略同时出信号，且方向一致。

- 有任一策略没出信号 → 整组丢弃（`not_all_signaled`）
- 方向不一致（有的 BUY 有的 SELL）→ 整组丢弃（`direction_conflict`）
- 同向数量不足 `min_agree_count` → 丢弃（`below_min_agree`）

**`vote`**：按权重投票。

- `buy_score` / `sell_score` 分别是 BUY / SELL 信号的权重和
- 分数高者胜；相等时看 `tie_policy`，`skip` 则丢弃（`tie_skip`）
- 胜出方向的**策略数**要 ≥ `min_agree_count`，注意这里数的是只数，不是权重和

## 为什么要有 and / vote

单策略信号天然带噪音，`or` 只会让交易更频繁、回撤更难看。`and` 用「多策略同时确认」换胜率，代价是信号数量骤减；`vote` 是折中，允许权重表达策略信心差异，但仍要求同向票数达标。

三者的取舍应该在回测里量化比较，不要凭感觉选。建议固定同一标的区间，分别跑 `or` / `and` / `vote`，对比交易次数、胜率、最大回撤与扣费后收益。

## 与 BLK、批量的配合

- BLK 解析出的标的池可以先导入 `data/blk_*.json`，再由批量脚本逐个回测；每个标的一次请求，组合配置写在同一个 `combination_config` 里。
- 批量脚本 `scripts/batch_backtest_runner.py` 支持 `--parallel-workers` 与多 `--base-urls` 并发，组合配置随任务下发。

## 排查

回测结束时日志会输出一行合成摘要，含 `mode`、`kept`、丢弃原因与票数：

```json
{"enabled": true, "mode": "vote", "kept": 2, "winner": "BUY", "buy_score": 3.5, "sell_score": 1.0}
```

常见的 `reason`：`no_signal`、`no_target`、`not_all_signaled`、`direction_conflict`、`below_min_agree`、`tie_skip`。看到 `not_all_signaled` 先确认 `strategy_ids` 里的策略是否都启用且在该周期有信号。
