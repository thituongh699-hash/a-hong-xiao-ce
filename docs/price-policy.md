# 指标价格与成交价格

行情适配器返回不复权 OHLC。TDX 读取本地原价，Tushare 使用 daily/stk_mins，AkShare 使用空 adjust，BaoStock 使用 adjustflag=3，JQData 使用 fq=None。修复后的缓存使用新命名，避免复用旧复权行情。数据库及自定义 API 必须声明 `data_provider.stored_price_mode=none`；这项声明不等于外部数据已被独立验证。已经复权、无法取得原价的数据不能用于本项目的成交模拟。

`data_provider.adjustment_mode` 只选择指标和信号价格：

- `none`：原价。
- `hfq`：原价乘当日累计后复权因子，除以回测首日因子。起始价格归一，之后不随未来事件重新定基。
- `qfq`：当前 K 线保持原价；除权日先将策略已保存的历史 OHLC 和价格状态乘以前一因子/当前因子，再计算指标。这是截至每个交易日的前复权，不能把回测结束日的价格尺度倒灌到过去。

统一因子来自 BaoStock 的 `backAdjustFactor`，通过独立 Python 子进程取得；使用除权生效日期查找当时的因子。查询有超时、完整游标检查、覆盖区间检查和版本化缓存。失败时不会用全 1 因子假装完成复权。因子数据库可能修订历史记录，本实现没有保存历史版本，因此不提供历史数据修订的 point-in-time 保证。目前统一路径支持沪深股票。

策略收到 `raw_close` 等原价字段和 `signal_multiplier`；资金比例下单必须按原价计算股数。策略发出的价格、止损和止盈在进入风控、撮合及费用计算前转换回原价。成交、持仓市值和资金账本始终使用原价。成交股数、成交量及成交金额不随复权价格缩放。

前复权需要重定基策略状态。内置策略支持该操作。自定义策略如果保存额外价格状态，需要实现 `rebase_signal_prices(code, ratio)`；只使用内置状态的策略可以显式声明 `supports_dynamic_qfq=True`。不满足条件的自定义策略在需要重定基时停止，并可改用后复权。

分红、送转尚未入账。因子不能确定现金金额、登记日权益、派息日、税额、新增股份上市日或可卖批次，不能从价格变化反推账户变更。复权回测检测到持仓跨因子变化日会失败，不生成正常收益报告。不复权模式可以运行，但收益不包含公司行动，且未取得因子时无法保证识别除权事件。真实近似实时交易同样会阻止未处理的除权持仓继续交易。

配置中心首次打开及数据源草稿变化时自动调用 `/api/config/test_price_readiness`。检测日线、分钟数据、原价口径及统一因子；仅测试草稿，不保存配置。报告中的 `baseline_meta.price_policy` 记录实际口径，旧报告缺少该信息时显示未验证。启动回测不会自动覆盖用户的复权设置或改写共享配置。

BaoStock 最小分钟周期为 5 分钟，1 分钟请求明确失败，不把 5 分钟 K 线伪装成 1 分钟。

统一复权支持沪深 A 股主板、创业板和科创板股票；指数、基金、B 股和其他市场没有已验证的统一复权路径，复权请求会明确失败。触发周期仅接受 1/5/10/15/30/60 分钟和日线，禁止将跨除权日的周线或多日原价聚合后按结束日因子直接复权。

前端启动单票回测或近似实时监控前也会检查已保存的数据源；近似实时要求分钟数据通过时效检测。检测运行在可终止的子进程中，30 秒超时后会结束并回收进程，凭证仅经标准输入传递，不写入命令行或测试报告。

回测基线的成本参数在任务上下文中生效，保留用户选择的复权模式，不写入共享配置，也不会互相覆盖。报告同时记录实际有效 K 线的首末日期和请求日期；请求区间超出数据覆盖时会提示。

实现前参考了 [Backtrader 的 broker 执行与现金账本源码](https://github.com/mementum/backtrader/blob/master/backtrader/brokers/bbroker.py)，并检查本项目与安装的 BaoStock/Mootdx SDK 实际调用。账户权益与行情复权分层处理；不从复权因子推算现金或股份到账。

TDX 日线优先读取最新本地 `.day` 文件，覆盖旧缓存中的同日价格；每个日期只保留一根日线。TDX 缓存使用 `tdx_raw_v2_` 命名，不复用旧缓存。数据适配器测试使用临时目录，避免合成测试行情写入用户的行情缓存。

分钟数据的近似实时就绪要求是：不早于最新日线日期、处于最近 3 个自然日内且不是未来记录。历史分钟文件仍可用于其实际覆盖区间的回测。长假可能触发保守的时效限制，交易恢复后需要重新检查。

## 回测时序与结算契约（2026-10-17）

主引擎从同一份已校验基础行情生成策略周期，不再额外读取供应商的高周期成品。分钟记录采用交易所结束时间：上午 `(09:30,11:30]`、下午 `(13:00,15:00]`；完整窗口完成后才向策略交付，再在下一根基础 K 线开盘模拟成交。缺失分钟、半个窗口或不完整日线不会被当作已完成周期。自定义数据源若采用开始时间，需要先转换为明确的结束时间口径。

因子变化且没有旧持仓时，跨除权日的待执行信号会取消，防止止损、止盈继续使用旧尺度。旧持仓跨事件仍因未实现公司行动账本而终止。

数据清洗只规范类型和排序，不前填缺失 OHLC。重复时间、错误 OHLC 包络、无效/非正价格、缺失或负量额会明确报错。分钟缓存只有覆盖请求内所有预期交易时段点才命中；缺少节假日/停牌证据时采用保守 cache miss。新修订值优先，TDX 日线同一交易日修订保留最后值，证券代码别名写入统一键。

每个策略账户的期末报告包含 `settlement`：现金、持仓市值、标的数与股数、已实现/未实现盈亏、费用及对账差额。买入费用保存在持仓批次成本中，卖出后分摊到已实现盈亏；费用披露不代表再次扣减。无外部资金流时应满足：`期末现金 + 持仓市值 = 初始资金 + 已实现盈亏 + 未实现盈亏`。期末因 T+1 或成交边界未能平仓时仍按原价估值，并显示未平仓。

风险峰值按每根基础 K 线更新，报告净值只保存每个交易日最后观察。旧报告缺少结算快照时显示“未提供”，不会以零冒充。新增成交次数与已平仓次数分开显示；旧 `trade_count` 继续表示已平仓次数。

普通服务入口和命令行回测均使用单次任务配置快照与运行时成本覆盖，不更改共享配置。报告同时记录周期生成政策和逐日涨跌停边界是否完整；没有边界时不宣称验证了真实涨跌停排队成交。
