## 本轮实现

1. **因果时序**：新增完成 K 线聚合器；分钟输入采用 end-stamped 约定，上午 `(09:30,11:30]`、下午 `(13:00,15:00]`。不足完整基础时间点的窗口不触发策略。日线驱动策略仍使用供应商原日线；分钟驱动下的日线需完整交易时段。
2. **成交边界**：主引擎保留供应商原有涨跌停和停牌字段；不再只抽取八个 OHLCV 字段。缺失逐日边界时报告明确披露，未将其描述为已验证的历史涨跌停模型。
3. **公司行动挂单**：因子变化时取消该股旧挂单，再由策略重新生成。已有持仓跨事件仍按原有边界终止，不从因子推算到账资金或股份。
4. **账户与风险**：买卖方向统一；加仓的显式保护价更新整仓保护，省略则保留，成交失败不更新。流水记录信号时间、成交模式和退出原因，期末强平可正确计数。
5. **数据入口与缓存**：统一严格 OHLCV 校验；重复时间、无效/非正价格、错误包络、缺失或负量额不再静默通过。分钟缓存按交易时段查缺口，修订值覆盖旧值；TDX 证券代码统一缓存键。日线同日修订采用明确的最后值优先规则，与原始重复时间拒绝规则区分。
6. **结算呈现**：最终账户快照不会被完成事件清掉；区分成交次数与已平仓次数，显示未平仓标的数及股数。平手不计亏损，未定义盈利因子显示 `--`，回撤在 UI 中统一为非负幅度，混合 ISO 日期可完整解析。
7. **资源**：风险峰值增量更新，日报净值只保留当日最后观察；普通回测、批量所用服务入口和 CLI 绑定任务配置快照；事件合并不再遍历整个队列判断同类事件是否等待中。

## 验证与量化效果

- 单元测试：612 项通过，排除需要外部网络的 `akshare_test.py`。
- 前端契约：29 项通过。
- Edge 真实页面与事件队列：账户和报告同为 100,100 元；实际买入 1 笔显示未平仓，现金 99,000、持仓 1,100、未实现盈亏 100、对账差额 0，0 页面异常。
- 未来分钟扰动对照：在 09:35 完成的五分钟信号，最早在下一基础 K 线 09:36 模拟成交；改变 09:39 的未来价格不影响此前成交。
- 回撤组件：4,000 根序列的中位时间约 **1.13 秒 → 0.003 秒**，逐步回撤校验和相同。仅代表该组件，不代表整个回测加速比例。
- 净值 Python 内存：5 策略×60,000 基础 K 线，逐 bar 300,000 条约 **64.19 MiB**，日报保留 1,250 条约 **0.27 MiB**；最终净值相同，盘中风险峰值另行保留。

完整工件：`reports/upgrades/2026-10-17/quant-correctness/`，包含引擎场景、日志、浏览器截图、性能前后对照及源码指纹。旧审计工件保留，避免把修复前证据覆盖成修复后结果。
