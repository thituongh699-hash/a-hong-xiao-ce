# 因子研究框架

`src/factor/` 是新增的因子研究层。目标不是再写一个因子，而是把「假设 → 数据 → 加工 → 检验 → 证伪 → 合成 → 组合 → 结论」固化成一条可复用的管线，并把研究纪律写成代码约束。

## 为什么要单独做一层

项目原有的因子研究是「一个因子一份脚本」：`scripts/research_low_reversal.py`、`scripts/research_obv_resonance.py`、`scripts/obv_alpha_statistics.py` 各自实现了截面比较、统计推断和成本假设。单个研究做得很细，但存在三个结构性问题：

| 问题 | 后果 |
|---|---|
| 每个脚本自己定义前向收益口径 | 不同因子的 IC 不可比较，也无法直接合成 |
| 没有强制样本外与参数扰动 | 结论容易停在「样本内看起来有效」 |
| 没有准入判定 | 因子做完就进策略库，失效后也没有退役依据 |

新框架不替换这些脚本，而是补上统一口径与准入判定：脚本继续做单因子的深度研究（事件研究、匹配、bootstrap 推断），框架负责横向比较、去冗余和给出可审计的结论。

## 八步流程与代码对应

| 步骤 | 落到哪里 | 关键约束 |
|---|---|---|
| 01 立题 | `spec.FactorSpec.hypothesis` | 不写经济假设的因子注册不上，抛 `FactorRegistryError` |
| 02 数据 | `panel.build_panel` | 整只剔除坏数据（重复日期、非正价格、OHLC 包络越界），剔除原因进报告 |
| 03 加工 | `preprocess.preprocess_cross_section` | 顺序固定：去极值 → 标准化 → 中性化 → 再标准化 |
| 04 检验 | `evaluate.evaluate_factor` | RankIC / ICIR / 同号率 / t 值、分层、衰减、换手 |
| 05 证伪 | `pipeline._param_stability`、`_universe_stability`、样本内外切分 | 参数 ±50% 扰动、标的池三等分、样本外保持率 |
| 06 合成 | `combine.build_combination` | 先按相关性去冗余（默认 |ρ| > 0.7 剔除），再等权/IC/ICIR 加权 |
| 07 组合 | `pipeline` 合成段 | 合成得分作为组合因子重跑一遍完整评估 |
| 08 结论 | `gates.judge` | 四道关卡逐条给出通过/未通过原因 |

## 口径硬约束

这几条是框架与一次性脚本最大的区别，改动任何一条都会改变结论，因此写死在代码里：

1. **前向收益从 T+entry_lag 开始算。** 默认 `entry_lag=1`，即 T 日收盘出信号、T+1 收盘建仓、持有 `horizon` 个交易日后离场。`entry_lag=0` 等于假设能以信号日收盘价成交，属偏乐观口径，需要显式指定。
2. **不重叠采样。** 截面按每 `horizon` 个交易日取样（`StudyConfig.horizon` 同时是持有期和取样步长）。逐日计算 h 日收益会让相邻样本共享同一段未来收益，t 值被系统性高估。
3. **可交易掩码。** 建仓日涨停买不进、停牌无成交、离场日跌停卖不掉，这些样本的真实收益不可实现，默认置为缺失而不是照算。涨跌停幅度按板块前缀近似（主板 10%、创业板/科创板 20%、北交所 30%）。
4. **预处理顺序不可换。** 先压极值再标准化，否则标准差被极值抬高；中性化会改变尺度，所以末尾再标准化一次。
5. **方向只在解读层生效。** 因子值保持原始经济含义，`direction=-1` 表示值越小越好；`*_adj` 字段统一是方向调整后的指标，关卡只看这些字段。

## 四道关卡

| 关卡 | 检查项 | 默认阈值 |
|---|---|---|
| 1 预测力 | \|IC\|、ICIR、IC 同号率、IC t 值 | 0.03 / 0.5 / 55% / 2.0 |
| 2 单调性 | 分层单调性、相邻逆序数、多空 t 值、多空胜率 | 0.8 / ≤1 / 1.5 / 55% |
| 3 稳健性 | 样本外 IC 保持率、参数扰动稳定性、分域稳定性、样本覆盖退市与历史 ST | 0.6 / 1.0 / 0.6 / 必须满足 |
| 4 可实现性 | 扣费后多头超额、换手率 | > 0 / ≤ 85% |

关卡区分三类状态，避免把「数据不够」误判成「因子无效」：

- **failed**：因子本身不过关 → 结论 `淘汰`。
- **weak / incomplete**：证据不足（样本外缺失、样本只含存续标的）→ 结论 `待补证`，可用但必须在报告里写明限制。
- **passed**：全部通过 → 结论 `通过`。

只有 `通过` 和 `待补证` 的因子会进入合成池（要求关卡 1、2 为 passed），`淘汰` 的因子不参与合成。

**当前项目的默认结论上限是 `待补证`**：内置股票池只有当前存续标的，没有历史成分股与退市样本，关卡 3 的覆盖度检查必然不过。这是刻意保留的——把数据缺口显式暴露出来，比给一个看起来通过的结论更有价值。

## 快速开始

命令行（合成数据验证链路）：

```bash
python scripts/run_factor_lab.py --demo
```

命令行（真实行情，走项目现有数据源）：

```bash
python scripts/run_factor_lab.py \
  --codes 600519,000001,000002,600036 \
  --start 2021-01-01 --end 2025-12-31 \
  --factors vol_20,mom_20,rev_5 \
  --horizon 20 --universe 自选池
```

输出在 `reports/factor-studies/<研究编号>/`：`report.json`（严格 JSON，可逐字复核）与 `index.html`（离线单文件报告，含 IC 柱状图与分层净值曲线）。

Python 调用：

```python
from src.factor import build_panel, run_study, StudyConfig

report = run_study(build_panel(bars), StudyConfig(
    factor_ids=("vol_20", "rev_5"),
    horizon=20,
    min_names=20,
    industry=industry_map,       # {代码: 行业}，不给则只做市值中性
    survivorship_complete=False, # 没有历史股票池时保持 False
))
print(report["summary"]["headline"])
```

HTTP 接口（已挂到 `server.py`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/factor` | 因子研究页面（选因子、填样本、跑研究、看结论） |
| GET | `/api/factor/catalog` | 因子目录、预处理口径、关卡阈值 |
| POST | `/api/factor/study` | 跑一轮研究，`demo=true` 走合成面板 |
| GET | `/api/factor/studies` | 历史研究列表 |
| GET | `/api/factor/study/{id}` | 报告 JSON |
| GET | `/api/factor/study/{id}/report` | 报告 HTML |

## 注册自定义因子

```python
from src.factor import FactorSpec, register

register(FactorSpec(
    factor_id="turn_20",
    name="20 日平均换手",
    category="量价",
    direction=-1,
    hypothesis="换手过高说明筹码分散、交易拥挤，后续收益偏低。",
    lookback=21,
    compute=lambda df, params: df["vol"].rolling(20).mean() / df["vol"].rolling(120).mean(),
    required_columns=("vol",),
    param_grid=({"window": 10}, {"window": 40}),
))
```

`compute` 只允许使用 T 日及之前的数据。实现上依赖 `rolling` / `shift`，禁止 `shift(-n)`；`tests/unit/test_factor_panel.py` 有截断未来数据的因果性用例。

## 产物与可复核性

- `report.json` 内的 `fingerprint` 是 `StudyConfig` 与数据质量的 SHA256 前 16 位，同配置同数据重跑必须得到同一指纹。
- 报告所有数值都由同一份 JSON 渲染，渲染层不重算、不挑最优参数。
- 合成数据模式会在 `warnings` 里强制标注「数值不能作为因子有效性证据」。

## 已知限制

- **幸存者偏差未解决。** 框架只是把它变成可判定的关卡，数据侧仍缺历史成分股、逐日 ST 状态与退市样本。
- **行业分类需要外部提供。** 未提供时只做市值中性，行业暴露留在残差里，报告会明确写出来。
- **涨跌停按前缀近似。** ST 的历史涨跌停幅度（5%）没有逐日还原，会用 10% 处理，偏宽松。
- **成本是一阶近似。** 用换手率 × 双边费率估算，没有冲击成本模型和容量测算；`cost_multiple` 只做压力测试。
- **未做多重检验校正。** 一次跑 20 个因子，最好的那个很可能是运气；框架没有实现 Deflated Sharpe 或 Bonferroni 类校正，需要研究者自己控制因子数量（建议一次不超过 10 个）。
